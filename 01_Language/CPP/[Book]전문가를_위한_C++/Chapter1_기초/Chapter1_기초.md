# Capter1 C++와 표준 라이브러리 초단기 속성 코스

## 1.1 C++의 기초

C++은 C언어에서 클래스가 추가되고 불편하거나 어색한 부분을 개선한 언어이다.

### 1.1.1 기본 구조

```cpp
// 예제
import <iostream>; // c++20 이전 버전에서는 #include <iostream>

int main()
{
    std::cout << "Hello, World!" << std::endl;
    return 0;
}
```

```Plaintext
[출력]

Hello, World!

```

이 기본 예제에서 포함되어 있는 개념을 알아보자

- 주석
- 모듈 임포트
- main() 함수
- I/O 스트림

----

### 주석

주석은 프로그래머에게 전달하는 메시지나 기록을 뜻한다. 프로그램이 컴파일하는 과정에서는 주석을 무시하고 실행이 된다

예시)

```cpp
// [메시지]

/*
[메시지]
*/
```

----

### 전처리 지시자

C++로 작성된 코드를 프로그램으로 만드는 빌드 작업은 세 단계로 나뉜다.

1. 전처리 (Preprocess) : 소스 코드에 담긴 메타 정보를 먼저 처리
2. 컴파일 (Compile) : 소스 코드를 머신이 읽을 수 있는 객체 파일(Object file)로 변환
3. 링크 (Link) : 변환한 여러 객체 파일을 엮어 애플리케이션(exe)로 만듬

지시자(Directive)는 전처리기에 전달할 사항을 표현하며 #include <[파일]> 처럼 #으로 시작한다. #include 지시자는 헤더 파일에 있는 내용을 현재 파일에서 자유롭게 사용 가능하게 모두 가져오도록 전처리기에 지시한다.

----

### 모듈 임포트

C++20 버전부터 새롭게 추가된 기능으로, 기존의 헤더 파일 방식을 대체하기 위해 도입되었다. 전처리 지시자와의 가장 큰 차이점은 컴파일 메커니즘에 있다.

기존의 #include 전처리 지시자는 헤더 파일을 텍스트 그대로 복사하여 붙여넣기 때문에, 여러 파일에서 같은 헤더를 불러올수록 컴파일 시간이 기하급수적으로 늘어나고 컴파일 과정의 메모리를 많이 잡아먹게 된다.

import를 사용하는 모듈 방식은 헤더 파일을 복사하는 것이 아니라, 미리 컴파일된 데이터를 '참조'하는 방식을 사용한다. 따라서 같은 모듈을 여러 곳에서 사용해도 중복 처리가 발생하지 않아 컴파일 속도가 비약적으로 빠르며, 기존 C/C++의 고질적인 문제였던 매크로 이름 충돌(오염)도 방지할 수 있다. (참고로, 프로그램이 최종 완성된 후 실제 실행될 때(Runtime)의 메모리 사용량이나 성능은 두 방식 간에 차이가 없다.)
